# 07. Encrypt secrets at rest in PocketBase

Priority: P1 · Effort: S (half day) · Type: fix

## Problem
API keys, forge tokens and OAuth client secrets are stored as plain JSON in the `settings` collection
(`store.setSetting`, `server.mjs:655`) and in `users.oauth2`. `docker-compose.yml` publishes the PocketBase
admin UI on 8090 (loopback only) with its superuser password in `.env`. A `pb_data` backup leaks everything.

## Lazy fix
- `PR_SCORER_SECRET` env, generated by `install.sh` like the PB password. If unset, derive it from
  `PB_ADMIN_PASSWORD` so existing installs need no migration step.
- Two stdlib functions: `seal(str)` with `aes-256-gcm` and a random IV, `open(str)`. Prefix `enc:` so old
  plaintext values still read.
- Apply inside `setSetting` and `getSetting` for keys matching `/token|secret|apiKey/i`. About 20 lines.
- Document rotation: change the env and re-save each secrets page.

## Done when
`select value from settings` in `pb_data/data.db` shows `enc:` values for tokens, and existing plaintext rows
still load.

## Skip
KMS or Vault. Add when an enterprise pilot asks, as a file path for the secret.
